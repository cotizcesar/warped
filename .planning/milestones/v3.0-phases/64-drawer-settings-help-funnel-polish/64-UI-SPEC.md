# Phase 64 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Project: Warped Android app (Kotlin + Jetpack Compose, Material 3). No shadcn — native Compose design system. Reuse existing components; no new design language (per 64-CONTEXT.md locked decision).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Android) |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, button rows |
| md | 16px | Default element spacing, card padding, screen margins |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps, sheet empty-state vertical padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: icon-only touch targets min 32–48dp (existing per-row delete 32dp hit area, FAB, drawer pills); title-row 52dp reserved icon slot in catalog cards (`titleEndPaddingDp`).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16sp (`bodyLarge`) / 14sp (`bodyMedium`) | Regular (400) | 1.5 |
| Label | 12sp (`labelSmall`/`labelMedium`) | Regular (400) | 1.4 |
| Heading | 16sp (`titleMedium`) title rows | Semibold (600) | 1.2 |
| Display | 20sp drawer brand / 22sp (`titleLarge` sheet title) | Bold (700) / Semibold (600) | 1.2 |

Drawer footer rule (DRAWER-03, locked): footer item labels MUST be 16sp Semibold — same as the New Chat label (`fontSize = 16.sp, fontWeight = Semibold`). Current 12sp footer labels are the defect to fix. Icon size stays 20–24dp; tint follows selection (accent when selected, `#9CA3AF` secondary otherwise).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1F1F1E` / system surface | Drawer, screen backgrounds, sheets |
| Secondary (30%) | `#2B2B29` | Cards, selected drawer rows, dialogs |
| Accent (10%) | `#D97757` | See reserved list below |
| Destructive | `MaterialTheme.colorScheme.error` | Delete confirmations, trash icons only |

Accent reserved for: filled CTA buttons ("Download a model", "Use in Chat", "Download a local model"), New Chat drawer label + icon, selected drawer footer item tint, section header icons (Help/Settings), Help step numbers, selected-card border. Never for destructive actions (those use error color).

Exact key names at implementer discretion — EN+ES pairing is mandatory.

## UI Considerations

> Planner: lift each numbered item into plan `must_haves` (these are the visual/interaction truths for Phase 64).

### 1. Model bottom-sheet empty state — CTA placement + target (DRAWER-01)

- File: `ui/chat/components/ModelSelector.kt` (`ModelSelectorSheet`, lines ~164–177). The "chat model drawer" in the success criteria is this bottom sheet (the nav drawer in `NavGraph.kt` holds conversations, not models).
- Current: bare centered `selector_no_models` text. Contract: keep the text, add BELOW it (vertical 16dp gap, centered column) a filled accent `Button` (`containerColor = #D97757`, white text, 8dp shape — same style as ModelsScreen "Use in Chat") labeled "Download a model".
- Behavior: tap MUST dismiss the sheet (`onDismiss()`) then navigate to Model Catalog (`Screen.HuggingFace`) via the existing `onNavigateToSelector`-style callback chain. ChatScreen owns the sheet, so the navigation callback is threaded from `ChatScreen` (add `onNavigateToCatalog` param, wired in `NavGraph.kt` chat destinations to `navController.navigate(Screen.HuggingFace)`).
- Back/persistence: no state change; sheet dismiss follows the existing `BackHandler` + scrim path.
- Strings: new EN+ES pair; reuse `hf_download_model` only if exact wording fits, otherwise new key.

### 2. Footer item order, sizing, delete-all position + confirm (DRAWER-03, DRAWER-04)

- File: `ui/navigation/NavGraph.kt` drawer content (~lines 250–298).
- Order (top→bottom, locked): New Chat → Recents list → **Delete all chats row** → divider → footer row [Models · Help · Settings].
- Footer labels: bump from 12sp to **16sp Semibold** to match New Chat (`fontSize = 16.sp`, `fontWeight = Semibold`); tint logic unchanged (accent when selected, `#9CA3AF` otherwise); icons stay 20dp. Row stays `SpaceEvenly`, each item `weight(1f)`. No Web Options item anywhere in the drawer.
- Delete-all-chats row: full-width `TextButton`, error-colored label (reuse `settings_delete_all` / existing delete-all string), placed at drawer bottom directly above the Models footer (below the `LazyColumn` recents, above the footer divider). Visible only when `conversations.isNotEmpty()` (empty recents → no row, no dead button).
- Confirm: reuse the EXISTING dialog pattern — `WarpedAlertDialog` with `settings_delete_chats_title` + plural `settings_delete_chats_msg`, confirm error-colored, dismiss Cancel. On confirm: `chatRepository.deleteAllConversations()` (or existing bulk-delete API), clear `activeConversationId` + `activeModelSelection.clearLastConversation()`, `engineManager.scheduleUnload()`, navigate to `Screen.NewChat`. Keep per-row delete (`delete_chat_title` dialog) untouched.
- State: dialog visibility via local `remember { mutableStateOf(false) }` in drawer content (same as per-row `showDeleteConfirm` pattern).

### 3. Remove Web Options from the model sheet (DRAWER-02)

- File: `ui/chat/components/ModelSelector.kt` lines ~179–185: DELETE the divider + `SectionHeader(cd_web_options)` + `WebOverrideSheetRow` block entirely. Remove now-unused `webOverride`, `globalWebEnabled`, `onWebOverrideSelected` params ONLY if no other caller needs them (ChatScreen is the sole caller — safe to simplify; otherwise keep params but stop rendering).
- Web grounding control lives in Settings only (existing `settings_grounding_title` switch — untouched). No replacement UI in the sheet.

### 4. Settings removals — exact cards/sections (SET-01, SET-02)

- File: `ui/settings/SettingsScreen.kt`. STRICTLY removals, no regrouping/restructure of remaining sections (locked).
- Remove A — Data section (lines ~133–175): entire `SettingsSectionHeader(Storage, settings_section_data)` item + the Card with chats/endpoints/models/presets counts + "Delete" chats button. Also remove the `showDeleteChatsDialog` `WarpedAlertDialog` block (~lines 63–80) and its ViewModel state (`showDeleteChatsDialog`, `chatCount`-only usages — keep counts if referenced elsewhere, delete if orphaned).
- Remove B — Security key-deletion (lines ~348–373): entire `SettingsSectionHeader(Lock, settings_section_security)` item + Card with `settings_security_desc` + `settings_delete_all_keys_btn` button. Also remove the `showDeleteKeysDialog` block (~lines 82–95). Keep `deleteKey` in the data layer for endpoint-deletion flows (programmatic only, no UI).
- Remain UNTOUCHED, in current order: Web section (grounding switch), Display section (code theme + font scale), App section (wizard card). Remaining sections keep 12dp `#2B2B29` cards, 16dp padding, 12dp `spacedBy`, `titleMedium Bold` headers with 18dp accent icons.
- Key rotation stays via endpoint edit-overwrite (`EndpointForm` apiKey field — untouched). Bulk chat delete lives ONLY in the drawer (§2).

### 5. Help numbered-steps rewrite scope EN+ES (HELP-01)

- File: `ui/help/HelpScreen.kt`. KEEP the `HelpSection` composable exactly (12dp `#2B2B29` card, 24dp accent icon + `titleMedium Bold` title, numbered steps `bodyMedium` with accent `"{i+1}. "` prefix, 3dp vertical step padding, 16dp card padding, 16dp section spacing). Single-scroll `LazyColumn`, no new components.
- Scope: rewrite ALL step strings short/minimal/to-the-point; hard requirement: NO Tavily steps, NO API-key steps anywhere (post-Phase-63). Builds on the Phase 63 `help_s7_step5` minimal fix. Section count/icons may shrink if steps collapse (agent discretion — fewer, shorter sections preferred over 8 long ones), but the numbered-steps card pattern stays.
- Strings: every touched `help_s*` key updated in BOTH `values/strings.xml` and `values-es/strings.xml`. User reviews wording in code review (locked) — keep each step to one short sentence.

### 6. Catalog "Use in Chat" placement + behavior (FUN-01)

- File: `ui/huggingface/HuggingFaceScreen.kt` (`CatalogModelCard` trailingActions, ~lines 317–335).
- Current downloaded state: delete trash icon only. Contract: for `downloaded == true` cards, render a compact filled accent `Button` ("Use in Chat", `#D97757` bg, white text, 8dp shape — mirroring `ModelsScreen.ModelCard`'s `use_in_chat` button) BESIDE the existing delete icon (Row: button `weight(1f)` + delete `IconButton` 22dp error tint, 8dp gap — same row pattern as ModelsScreen lines 399–415). Active-download and failed states unchanged.
- Behavior: tap MUST activate the model for chat AND navigate to chat — mirror the proven `ModelsViewModel.useLocalModel` → `pendingChatId` → `onUseInChat(id)` → `Screen.ChatDetail(id)` chain. `CatalogViewModel` needs the equivalent activation path (reuse the same repository/selection calls; check current activation routing before wiring). Navigation target: chat with the activated model (`Screen.NewChat` or `Screen.ChatDetail`, matching whichever the ModelsScreen flow resolves to).
- Reuse existing `use_in_chat` string (EN+ES already exist). No new design language.

### 7. Models & Endpoints empty-state buttons + targets (FUN-02, FUN-03)

- File: `ui/models/ModelsScreen.kt` empty-state branch (~lines 247–262). (Note: `EndpointsScreen.kt` standalone is legacy — the live route is `Screen.Selector → UnifiedSelectorScreen`; apply CTAs to `ModelsScreen` and mirror in `UnifiedSelectorScreen`'s empty state if it has one.)
- Current: single `OutlinedButton(add_model)` opening the add-wizard. Contract: replace with TWO filled/tonal CTAs in a centered column, 8dp spacing:
  1. "Download a local model" — filled accent `Button` → `onOpenHuggingFace()` (navigates to `Screen.HuggingFace` catalog).
  2. "Add a new Endpoint" — `OutlinedButton` (8dp shape) → `viewModel.showEndpointForm()` (opens endpoint creation inline, same as the wizard's third row).
- Keep the existing heading (`no_models_endpoints_yet`, `bodyLarge #9CA3AF`) + hint (`models_empty_hint`, `bodySmall`) above the buttons. Only render when `models.isEmpty() && endpoints.isEmpty() && !isImporting && activeDownloads.isEmpty()` (existing gate — unchanged). The FAB + add-wizard dialog stay as-is for non-empty states.
- Strings: new EN+ES pairs for both buttons.
