# Plan 41-01: Thinking Mode — Domain + Helper Wiring

**Phase:** 41 — Thinking Mode + Model Benchmark
**Requirements:** THINK-01, THINK-02, THINK-03

## Goal

Plumb the `enableThinking: Boolean` parameter end-to-end through the unified helper surface. Wire LiteRT-LM and LM Studio helpers so the reasoning trace flows through `StreamToken.Delta(reasoning = ...)` only when the user has the toggle on; otherwise drop reasoning deltas at the helper boundary.

## Scope

- `app/src/main/java/com/warped/data/local/inference/LiteRtLlmHelper.kt` — change `runInference()` to forward `enableThinking` to the underlying `LiteRTLmProvider.chat()` call. If false, transform the returned `Flow<StreamToken>` to clear/drop the reasoning channel.
- `app/src/main/java/com/warped/data/remote/provider/LmStudioHelper.kt` — same shape: forward `enableThinking` and filter reasoning when false.
- `app/src/main/java/com/warped/data/local/inference/LiteRTLmProvider.kt` — confirm reasoning emission path; add an `enableThinking` parameter to `chat()` if not already accepted (passes through to LiteRT-LM 0.13.1 config).
- `app/src/main/java/com/warped/data/remote/provider/LMStudioProvider.kt` — confirm `reasoning_content` parsing path is already in place from v1.8 (`StreamToken.Delta(reasoning = ...)` emission); no API change unless missing.
- `app/src/main/java/com/warped/domain/model/StreamToken.kt` — confirm `Delta` carries `reasoning: String? = null` and `Done` carries `reasoning: String? = null`. Add fields if missing.

## Implementation

1. Read current `StreamToken` definition; add `reasoning: String?` fields if not present.
2. `LiteRTLmProvider.chat()`: if it currently always emits reasoning (when the LiteRT-LM library partial-thinking callback fires), accept `enableThinking: Boolean = false` and gate emission server-side. If the lib doesn't expose a server-side gate, the helper filters client-side (Step 4).
3. `LiteRtLlmHelper.runInference(request, enableThinking)`:
   ```kotlin
   val raw = liteRTLmProvider.chat(request, enableThinking)
   return if (enableThinking) raw else raw.map { token ->
       when (token) {
           is StreamToken.Delta -> token.copy(reasoning = null)
           is StreamToken.Done  -> token.copy(reasoning = null)
           is StreamToken.Error -> token
       }
   }.flowOn(Dispatchers.Default)
   ```
4. `LmStudioHelper.runInference(request, enableThinking)`: same pattern, LM Studio always emits if model supports it — filter client-side when false.
5. Drop the legacy `chat(request)` Flow drain in both helpers' `runInference()` (the v1.5 `scope.launch { provider.chat(...).collect {} }` is a double-invocation; remove and rely on the caller-collected Flow for cancellation via `activeJob` tracking).
