Exceptions: 48dp minimum touch targets for voice-send toggle, dictation mic, gated-button tap target, caption expand affordance, and bubble play/pause per Material accessibility minimums (not a spacing token — a hit-target floor). Source: Phase 67/68 contract, unchanged.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` / `background` (theme-resolved) | Chat background, surfaces |
| Secondary (30%) | `colorScheme.surfaceContainer` (input pill, cards) | Chat input pill, message bubbles, draft card background |
| Accent (10%) | `colorScheme.primary` | Voice-send GraphicEq icon tint when enabled, draft/bubble LinearProgressIndicator fill, send affordance |
| Destructive | `colorScheme.error` | Draft delete affordance only |

Accent reserved for: voice-send enabled icon tint, draft + bubble LinearProgressIndicator fill, send affordance. Never for error text, never for the delete affordance (error color owns those). Never for the disabled gated button (reduced opacity of `onSurface`, never primary — a disabled affordance must not wear the accent). Source: Phase 67/68 contract, extended with the disabled-state rule.

Gated-button color rule (locked by CONTEXT.md — disabled-with-reason, never hidden): disabled voice button renders the same GraphicEq glyph at reduced opacity (`contentAlpha`-style disabled `onSurface`, ~38% per Material disabled-content convention) with no container recolor, no error-red tint. Reason hint text ("Needs audio model" / remote variant) in `onSurfaceVariant`. The button remains tappable — disabled visual state, enabled tap handler that opens the explainer. Never `enabled = false` with no handler (that would be a dead button, forbidden by VMSG-04/VMSG-08).

Caption color rule: transcript caption text `onSurfaceVariant`; expand affordance ("Show more" / "Show less") tinted `colorScheme.primary` (text-button language). Duration-only fallback caption in `onSurfaceVariant` (informational, never error-red — missing STT is not a user error).

Active-mode rule: the active input mode's button wears `colorScheme.primary` tint; the inactive sibling renders in default `onSurfaceVariant`. When neither mode is active, both render in default `onSurfaceVariant` (voice-send enabled) or disabled styling (gated). Tint is the primary active-mode signal. Amendment (post-implementation, UI review 20/24 fix 3): the shipped `primary@50%` IconButton container behind the active glyph is blessed as the inherited pill convention — it predates this phase (Phase 65 dictation listening state, Phase 67 recording state) and keeps both modes visually consistent. The Phase 68 no-recolor rule governs progress surfaces, not the input-row active button.

## Screens / Surfaces (Phase 69 scope)

Exactly two surfaces change, both in `ChatScreen.kt` / `ChatInputBar.kt`. No new screens. One new Help section (existing Help screen, new voice subsection). No drawer/settings/catalog chrome changes — the catalog link reuses the existing Phase 64 Use-in-Chat deep link.

### Surface 1 — Chat input row (differentiation + gating + coachmark)

- Visual anchor (focal point): the input-row voice/dictation button pair draws the eye first — the active mode's primary-tint button is the single accent in the row; the first-use coachmark anchors there. All other row elements stay neutral chrome.
- Voice-send keeps the GraphicEq waveform glyph; dictation keeps the Mic glyph (locked by CONTEXT.md — continuity with 67/68, zero asset churn). Glyphs never swap, never share a toggle — two separate buttons side by side in the input row.
- Mutual exclusion: starting voice-send recording stops an in-progress dictation session (and vice versa). Both buttons reflect the active mode via the active-mode tint rule above. TalkBack descriptions stay distinct: "Record voice message" vs "Dictate text" (locked by CONTEXT.md), with `stateDescription` announcing the active mode (Phase 65 pattern).
- First-use coachmark: on first render of the enabled voice-send button (per-install flag in DataStore, Preferences flavor per STACK.md), a one-shot Material 3 `Tooltip`/`PlainTooltip`-style coachmark anchors to the voice-send button with the documented copy. Dismisses on first tap outside, first voice-send tap, or first dictation tap — whichever comes first. Never re-shows after dismissal. No full onboarding tour (declined, locked by CONTEXT.md). Exact shape (Tooltip vs custom popup) at executor's discretion within Material 3 conventions — this is the agent's-discretion item from CONTEXT.md.
- Text-only model gating (VMSG-04): when `ModelAllowlistRepository.capabilities.audio == false` for the selected local model, the voice button renders the disabled gated style (rule above) with the "Needs audio model" hint. Gate evaluates on model select + on chat open, flips live on model switch (locked by CONTEXT.md). Tapping the gated button opens the explainer surface (agent's discretion: Snackbar with action vs bottom sheet — must carry the documented explainer copy + catalog link action; Snackbar with a "View models" action via the existing SnackbarHost channel is the recommended default, consistent with Phase 65's Snackbar + escape pattern). Explainer links to the model catalog (Phase 64 Use-in-Chat wiring — no new navigation).
- Remote endpoint gating (VMSG-08): when the active provider is remote (provider type != local), the same disabled-with-reason pattern with the remote reason copy. "Learn more" action opens the new Help voice subsection (EN+ES). Gate helper is keyed on provider type + audio capability (locked by CONTEXT.md) — no hardcoded local-only checks at call sites, so a future milestone can unlock remote voice-send without UI rework.
- Draft-kept rule (locked by CONTEXT.md): a model switch or endpoint switch with an in-progress draft keeps the draft (file + caption input) but blocks send with the reason — send tap on a gated configuration shows the explainer, never silently drops, never attempts the send. Applies identically to text-only and remote gates.

### Surface 2 — Own voice bubbles (transcript captions)

- Small caption under the player row inside own sent voice bubbles (Phase 68 bubble chrome unchanged — caption slots underneath the play + progress + duration row without re-layout, per the Phase 68 forward-compat lock). Caption text Label 14sp `onSurfaceVariant`, 2-line max with ellipsis + "Show more" expand affordance; expanded state shows full text + "Show less". Expand affordance only when the transcript exceeds 2 lines.
- Transcript attaches on send from the parallel on-device STT session (existing `VoiceDictationManager`/`SpeechRecognizer`, device-locale per Phase 65 pattern, VM-owned); stored as-is in the Room `transcript` column (Phase 68 migration 17→18 placeholder now filled), so captions survive restarts. No translation of stored captions.
- STT-unavailable fallback: duration-only caption with the documented fallback copy (Label 14sp `onSurfaceVariant`) — honest, never empty, never a fake transcript. Voice-send is never blocked by missing STT (locked by CONTEXT.md).
- Captions only on own sent voice bubbles — received/model-side audio is future VF-03, out of scope. No caption row on assistant bubbles.

### Help voice subsection (existing Help screen)

- New short subsection in the Help screen (Phase 64 EN+ES rewrite is the landing spot) covering: voice message vs dictation, the 60 s cap with 30 s model note (Phase 67 copy, reused), and the local-only limitation with the documented Help copy. Reached via "Learn more" from the remote-gate explainer. EN+ES strings required (Phase 64 precedent).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Send voice message (draft send button content description — unchanged from Phase 68) |
| Coachmark | Voice message (first-use coachmark anchored to the GraphicEq button; dismisses on first interaction) |

| Text-only explainer | Voice messages need an audio model. Switch to an audio-capable model to send voice. (explainer surface + "View models" action linking to the catalog) |
| Remote gate hint | Device-only for now (inline hint beside/below the disabled voice button, Label 14sp `onSurfaceVariant`) |
| Remote explainer | Voice messages stay on this device for now. (one-line reason + "Learn more" action opening the Help voice section) |
| Help voice section | Voice messages are transcribed on this device and sent only to audio-capable local models. Dictation types what you say; voice messages send audio the model hears. |
| Transcript expand | Show more / Show less (caption expand/collapse affordance, shown only when transcript exceeds 2 lines) |
| Transcript fallback | 0:12 voice message (duration-only caption when STT unavailable — duration interpolated, honest, never a fake transcript) |
| Empty state heading | n/a — no new empty state in this phase |
| Empty state body | n/a |
| Error state | n/a — gating uses explainer surfaces, not error states; sub-1 s and missing-file copy unchanged from Phase 68 |
| Unavailable state | Voice clip unavailable (missing-file bubble row — unchanged from Phase 68) |
| Destructive confirmation | Delete voice draft: no confirmation dialog (unchanged from Phase 68) |

Bilingual note: all new user-visible strings above (coachmark, gate hints, explainers, Help section, expand affordance, fallback caption) must be added to `strings.xml` with ES translations following the existing `values-es` pattern. Phases 67/68 added `voice_msg_*` strings — new keys follow the same prefix (e.g. `voice_msg_coachmark`, `voice_msg_gate_audio_hint`, `voice_msg_gate_remote_hint`, `voice_msg_transcript_fallback`). TalkBack descriptions that already exist are unchanged and need no new keys.
