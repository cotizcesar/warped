|------|-------|-------|

Accent reserved for: voice-send button icon tint, recording amplitude-bar fill, send affordance. Never for error text, never for the cancel affordance (error color owns those).

Recording-state color rule (locked by CONTEXT.md): inline `mm:ss` timer + amplitude bar render in `onSurfaceVariant` normally; both switch to `colorScheme.error` in the last 10 s (50–60 s). No other color change during recording — no pulsing background, no pill recolor.

## Screens / Surfaces (Phase 67 scope)

Exactly one surface changes: the chat input row in `ChatScreen.kt` (`ChatInputBar` + `bottomBar` slot). No new screens, no new dialogs, no drawer/settings changes.

### State 1 — Idle (default)

- Voice-send button (waveform/audio-clip glyph — `Icons.Filled.GraphicEq`-family or equivalent audio-clip vector, NEVER a mic glyph) sits in the chat input pill beside the existing STT dictation mic (Phase 65). Both visible when `speechAvailable` and model permits.
- Tap-to-start / tap-to-stop (not hold-to-record). Content description: "Record voice message" (idle).
- Sub-1 s clips are KEPT in this phase (no rejection — Phase 68 owns the <1 s guard).

### State 2 — Recording (active)

- Input row is replaced inline by the recording row: `mm:ss` timer + horizontal amplitude bar + explicit cancel (X) + tap voice-send button again to stop (stop = tap-to-stop on the same button, content description flips to "Stop recording").
- Live timer ticks each second; amplitude bar fills from live `MediaRecorder.maxAmplitude` samples on a ~100 ms cadence. Both turn `colorScheme.error` red in the last 10 s.
- Mutual exclusion (locked): starting voice recording stops STT dictation; starting dictation stops voice recording. Exactly one input mode live at a time.
- Starting a second recording while one is active is impossible by construction (single toggle button).
- TalkBack: recording row announces state via `stateDescription` (Phase 65 pattern) — "Recording, 0:12" style live region updates at most every 5 s to avoid TalkBack spam.

### State 3 — Auto-stopped at 60 s (clip kept)

- Recorder auto-stops at exactly 60 s, clip is KEPT (never auto-sent, never discarded on cap).
- Toast: "60s limit reached" (`Toast.LENGTH_SHORT`, shown once per auto-stop event — not per recomposition).
- After auto-stop the UI returns to Idle state with the clip retained in memory for send (file in `filesDir/voice/`); send path is identical to manual stop.

### State 4 — Send with >30 s note

- Tapping send transmits voice clip + optional caption text as one user bubble via the existing `ChatViewModel.sendMessage(text, images, audioBytes)` path.
- Whenever the clip exceeds 30 s, a user-visible note "First 30s sent to model" is shown (never silent truncation, never block >30 s sends). Placement: `SnackbarDuration.Short` via the existing `SnackbarHost` error/info channel in `ChatScreen` — consistent with existing non-blocking notices.
- Failed send keeps the file for retry (basis for Phase 68 draft). Cancel (X) during recording discards the file + deletes bytes immediately.

### Gating (minimal — full UX in Phase 69)

- Text-only model (allowlist `capabilities.audio == false` for the selected local model): send disabled + toast on attempted voice send. Never a dead button with no feedback.
- Remote endpoint selected: voice-send path blocked minimally in this phase (full local-only explanation lands in Phase 69, VMSG-08).
- Model loading (`isLoadingModel`): whole input bar locks, including the voice-send button (existing gate applies).

### Permission flow (Phase 65 pattern reuse)

- First tap on voice-send with no `RECORD_AUDIO` grant: inline rationale, then system request.
- Denied (transient): graceful Snackbar, recording never starts, no crash.
- Denied permanently ("don't ask again"): Settings-escape Snackbar with action (existing `SnackbarWithAction` → `OPEN_APP_SETTINGS` channel).
- Rotation: recording state survives via VM-owned `VoiceMessageRecorder` (ViewModel survives config change). Backgrounding auto-stops and keeps the clip (no mic-type FGS — out of scope).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Record voice message (voice-send button content description, idle state) |
| Stop action | Stop recording (voice-send button content description, recording state) |
| Cancel action | Cancel recording (X button content description — discards file immediately) |
| Empty state heading | n/a — no new empty state in this phase |
| Empty state body | n/a |
| Error state | Microphone access needed — grant permission to record voice messages (denied-permission Snackbar + retry path) |
| Cap notice | 60s limit reached (toast, auto-stop event only) |
| Truncation note | First 30s sent to model (Snackbar, whenever clip exceeds 30 s) |
| Destructive confirmation | Cancel recording: no confirmation dialog — single tap on X discards immediately per VMSG-01 (destructive action is instant and undoable-by-re-recording; consistent with locked CONTEXT.md decision) |

Bilingual note: Help/empty-state copy in this app ships EN+ES (Phase 64 precedent). The four user-visible strings above (cap notice, truncation note, permission Snackbar, rationale) must be added to `strings.xml` with ES translations following the existing `values-es` pattern.
