<threat_model>
- T-70-01 (prompt injection via document content): document text is untrusted — DocumentPrompt.sanitize strips hijack lines and escapes delimiter collisions before fusion (WebContextSanitizer precedent); the executor feeds only the sanitized block, never raw file bytes.
- T-70-02 (memory exhaustion via large file): pre-read size check caps the read at perPageBudget(contextSize, 1); decode happens on Dispatchers.IO in bounded chunks — a hostile 500 MB .txt cannot OOM the UI thread or the turn.
- T-70-03 (tool-name spoofing): exact-match dispatch only — read_text_file joins the same AGENT-04 allowlist; unknown names return unknownToolMessage and never execute.
- T-70-04 (stale attachment grounding): executor binds the document block to the current turn only; a missing attachment feeds the degradation string, never a previous turn's content.
</threat_model>
