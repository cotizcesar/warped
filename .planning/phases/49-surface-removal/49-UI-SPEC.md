# Phase 49 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Phase type: **removal-only** — no new screens. This contract locks what disappears,
> what stays byte-identical, and the exact copy/styling of the three retargeted
> surfaces (chat input, legacy transcript rows, static model catalog).

**Sources:** 49-CONTEXT.md (locked decisions), REQUIREMENTS.md DEL-01..DEL-06,
STATE.md / ROADMAP.md (v2.2 scope), WarpedTypography / WarpedShapes /

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px/dp | Icon gaps, inline padding, badge inner padding |
| sm | 8px/dp | Compact element spacing, card internal gaps |
| md | 16px/dp | Default element spacing, screen horizontal padding |
| lg | 24px/dp | Section padding, dialog internal padding |
| xl | 32px/dp | Layout gaps |
| 2xl | 48px/dp | Major section breaks |
| 3xl | 64px/dp | Page-level spacing |

Exceptions (inherited, retained — not introduced by this phase): 12dp card
corner radius + card content padding (`WarpedShapes.medium`, existing
`RoundedCornerShape(12.dp)` cards in Settings/Models/catalog), 6dp badge gaps,
20/28/40dp icon and touch-target sizes (existing send/stop/image buttons).
No new non-scale spacing value may be introduced in this phase; deletions must
not leave orphaned `Spacer` heights behind (e.g. the 8dp spacer under the
removed skill row goes with it).

## Typography

Touched surfaces use exactly 4 sizes and 2 weights (from `WarpedTypography`;
no new text styles):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16sp | Normal (400) | 1.5 (24sp) |
| Secondary | 14sp | Normal (400) | 1.43 (20sp) |
| Label | 12sp | SemiBold (600) | 1.33 (16sp) |
| Heading | 20sp | SemiBold (600) | 1.4 (28sp) |

Rules: chat transcript body stays `bodyMedium`/`bodyLarge` as today; meta chips
and badges use Label; card titles and dialog titles use Heading (`titleLarge`
20sp SemiBold); stats/reasoning footnotes keep existing italic muted style.
`titleMedium` 16sp Medium usages in touched files map to Body (no new Medium
weight declarations in this phase).

## Surfaces: Remove / Retain / Retarget

### 1. Chat input bar (`ChatInputBar.kt:110-118`) — REMOVE skill row

- Delete the `SkillChipsRow` call site, its 8dp trailing `Spacer`, the
  `skillEnabled` / `onToggleSkill` parameters, and `SkillChipsRow.kt`.
- The `OutlinedTextField` becomes the top row of the input card; Row 2
  (image + Thinking toggle | model + send/stop) is unchanged.
- Thinking toggle, image attach, send/stop behavior, placeholder
  (`type_message` "Type a message…"), 40dp touch targets, and
  `navigationBarsPadding` are retained byte-identical.
- Icon-only actions keep their accessibility labels (no label-fallback gap):
  send ("Send"), stop ("Stop"), image attach ("Add image"), drawer/menu
  ("Menu") `contentDescription`s are retained unchanged; state changes
  (send ↔ stop) keep announcing the visible action.
- No replacement UI: the input card simply starts 8dp+chip-height shorter.

### 2. Legacy transcript rows (`MessageBubble.kt:62-65`) — RETAIN read-only

- The `Role.TOOL` early-return branch is kept as the sole legacy renderer.
  Persisted tool rows render as the existing collapsed transcript row
  (`ToolResultRow`): Thinking-panel styling, `bodyMedium`, muted `#545450`
  italic, 16dp start indent, expand chevron (16dp, `contentDescription`
  via `formatToolTranscriptA11y`), collapsed by default, summary on expand.
- Read-only: no retry, no re-run, no dismiss, no error color on legacy rows.
- Delete `ToolErrorRow` and `NoToolSupportNotice` composables — no new tool
  calls can be produced, so live tool-error/notice surfaces must not exist.
- Local + remote prompt builders drop `TOOL` special-casing except this render
  path (code concern; no visual change).

### 3. Settings (`SettingsScreen.kt:119-162`) — REMOVE HF token section

- Delete the entire "Hugging Face" section header + card: "Access Token" title,
  "Token configured" / "Required for gated/private models" status line, token
  `OutlinedTextField` + "Save" button, "Remove token" button.
- Remaining sections (Data, Display, App, Security) keep order, copy, 12dp
  `spacedBy` rhythm, 12dp cards, 16dp content padding. The list collapses
  automatically — no replacement section, no placeholder text.
- `SettingsUiState` HF fields and `storeHuggingFaceToken` call site go with it
  (code concern).

### 4. Model discovery — RETARGET to static catalog (DEL-05)

- `HuggingFaceScreen.kt` search surface is deleted: search `OutlinedTextField`
  + supporting text ("Type to search..." / "Enter 3+ characters to search"),
  400ms debounce search, `SearchResults` list, gated-model error branch, and
  the "Open on Hugging Face" button.
- Replacement is a **static catalog screen** reusing the existing
  `ModelListCard` visual pattern (storage icon + title + subtitle + capability
  badges + description + `OutlinedButton` "Download" aligned end, 14dp card
  padding, 8dp list spacing):
  - `TopAppBar` title: "Model catalog", back navigation "Back to models".
  - One card per `model_allowlist.json` entry (3 models): `displayName` as
    title, `modelFile` as subtitle, size from `sizeInBytes`, capability badges
    for `vision` / `audio` only (no `tools` / `thinking` badges —
    `supportsFunctionCalling` is false for all entries; `deriveCapabilities`
    tools/thinking branches are deleted).
  - Download flow reuses the existing inline progress pattern
    (`LinearProgressIndicator` + "downloading… (N%)" + bytes/speed line +
    Pause / Resume / Cancel `TextButton`s) backed by
    `ModelDownloadManager`/`Worker` with no `Authorization` header.
  - No search field, no debounce, no loading shimmer for search, no gated
    filtering.
- Add-model wizard (`ModelsScreen.kt:144-154`): the "Download from Hugging
  Face" entry is relabeled to title "Download model", body "Choose from the
  built-in catalog", icon `Icons.Filled.Download`; it navigates to the static
  catalog. "Import Model File" and "Connect to an API" entries unchanged.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Use in chat |
| Secondary CTA | Download |
| Catalog title | Model catalog |
| Wizard catalog entry | Download model / Choose from the built-in catalog |
| Empty state heading | No models or endpoints yet |
| Empty state body | Tap Add Model to download one from the catalog or import a file. |
| Catalog load failure | Couldn't load the model catalog. Restart the app and try again. |
| Download 401 error | Download failed (unauthorized). The server rejected the request — check your connection and try again. |
| Download interrupted | Interrupted · {downloaded} downloaded (+ server message if present) + Delete partial file |
| Destructive confirmation — Delete model | Delete model: Delete {name} ({size}) from the device? [Delete / Cancel] |
| Destructive confirmation — Delete endpoint | Delete endpoint: Delete {name} ({type})? This cannot be undone. [Delete / Cancel] |
| Destructive confirmation — Delete All Chats | Delete All Chats: This will permanently delete all {n} conversations and their messages. This cannot be undone. [Delete All / Cancel] |
| Destructive confirmation — Delete all keys | Delete All API Keys: This will permanently delete all stored API keys. This cannot be undone. [Delete All / Cancel] |

Rules: every destructive action uses the existing `WarpedAlertDialog` pattern
(confirm in `error` color, explicit Cancel). No confirmation dialog is removed
or downgraded to a snackbar in this phase. The 401 message must not reference
any token, Settings screen, or Hugging Face. The strings `search_models`,
`search_models_hint`, `search_minimum_length`, `hugging_face_suggestions`,
and `download_from_hf*` are deleted with the search surface (or repurposed
only for the wizard relabel above).

## Visual Hierarchy

- Chat (primary screen): focal point is the transcript column (assistant text
  left / user bubble `#121212` right, max 340dp); the input card is secondary;
  the "Use in chat" / Send accent elements are the only elements that draw the
  eye by color. Removing the skill row does not move the focal point.
- Model catalog: focal point is the card list (displayName title first);
  the Download `OutlinedButton` (end-aligned) is the per-card anchor.
- Settings: focal point is the section list; deleting the Hugging Face section
  moves Data to the top — no reordering of the remaining sections.
