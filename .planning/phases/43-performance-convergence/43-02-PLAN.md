# Plan 43-02: DI & Network scoping (PERF-07, PERF-08) + LmStudioHelper.activeCall fix

**Phase:** 43 — Performance Convergence
**Requirements:** PERF-07, PERF-08

## Goal

Audit every Hilt `@Provides` to ensure it is scoped (`@Singleton` or `@ViewModelScoped`); no eager binding of heavyweight classes at the `SingletonComponent`. Also tune the OkHttp interceptor chain: SSE calls get `retryOnConnectionFailure(false)` + `callTimeout(60.seconds)` + a `Cache(50MB)`. Also fix the pre-existing `LmStudioHelper.activeCall` bug from Phase 40.

## Scope

- `app/src/main/java/com/warped/di/*.kt` (audit each `@Provides`)
- `app/src/main/java/com/warped/data/remote/network/*.kt` (SSE `OkHttpClient` builder)
- `app/src/main/java/com/warped/data/remote/provider/LmStudioHelper.kt` (fix `activeCall` assignment)
- `app/src/main/java/com/warped/data/repository/ProviderRouter.kt` (verify no eager singleton of LlmModelHelper — uses `dagger.Lazy<>`)

## Implementation

### 1. Hilt audit (PERF-07)
- Walk every `@Provides` in `DatabaseModule`, `NetworkModule`, `SecurityModule`, `SyntaxModule`, `ProviderModule`, `LlmHelperModule`, `HuggingFaceModule`, `InferenceModule`, `PromptLabTaskModule`.
- Add missing scopes. Document each in a one-line comment in the module.
- Verify `EngineManager` is `@Singleton` and `LiteRtLlmEngine` (if exposed) is `@ActivityRetainedScoped` or `@ViewModelScoped`, NOT `@Singleton`.
- `ProviderRouter` should use `dagger.Lazy<LlmModelHelper>` for the per-helper injection (already does — verify).

### 2. OkHttp tuning (PERF-08)
- In `NetworkModule.kt`, add a `@Named("sse")` `OkHttpClient` provider with:
  - `retryOnConnectionFailure(false)` (SSE: do not auto-retry, server must explicitly emit event)
  - `callTimeout(60.seconds)`
  - `Cache(File(context.cacheDir, "okhttp-sse"), 50L * 1024 * 1024)` (50MB)
  - `Cache-Control: no-cache, no-store` headers via interceptor
  - `addInterceptor { chain -> chain.proceed(chain.request().newBuilder().cacheControl(CacheControl.Builder().noCache().noStore().build()).build()) }`

### 3. LmStudioHelper.activeCall fix
- Locate the existing `activeCall: AtomicReference<Call?>` field.
- In `createCall(...)` (or wherever OkHttp `Call` is built), add `activeCall.set(call)`.
- In `onResponse` or `onFailure`, add `activeCall.set(null)`.
- Verify `stopResponse()` actually cancels the call.
