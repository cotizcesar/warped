The auto-detection algorithm:
```kotlin
private fun autoDetect(code: String): String {
    // Tokenize code into lowercase words, filtering out short tokens
    val words = code.split(Regex("[\\s(){}\\[\\];:,.=<>!+\\-*/%&|^~?'\"`@#\$\\\\]+"))
        .map { it.lowercase() }
        .filter { it.length >= 2 }
        .toSet()
    val scores = LANGUAGE_KEYWORDS.map { (lang, keywords) ->
        lang to words.intersect(keywords).size
    }
    val best = scores.maxByOrNull { it.second } ?: return "plaintext"
    return if (best.second >= 2) best.first else "plaintext"
}
```
- Confidence threshold: minimum 2 distinct keyword matches. Below that → "plaintext".
- For JSON and YAML (empty keyword sets): will always score 0 → falls through to "plaintext". This is intentional — JSON/YAML are handled structurally by the TypeMapper/DEFAULT language.

**File 1: `TypeMapper.kt`**
An `internal object TypeMapper` (stateless, no DI) with a single public function:

```kotlin
internal object TypeMapper {
    fun map(structure: dev.snipme.highlights.model.CodeStructure, code: String): List<SyntaxToken>
}
```

The `map()` function implements this algorithm:

**Step 1 — Map Highlights categories to TokenType:**
Create a mutable list of SyntaxToken. For each CodeStructure field, create tokens:
- `structure.keywords` → `TokenType.KEYWORD`
- `structure.strings` → `TokenType.STRING`
- `structure.comments` → `TokenType.COMMENT`
- `structure.multilineComments` → `TokenType.COMMENT`
- `structure.annotations` → `TokenType.PROPERTY`
- `structure.marks` → `TokenType.TAG`
- `structure.literals`: extract text via `code.substring(loc.start, loc.end)`. If lowercase text is in `setOf("true", "false", "null", "nil", "None", "undefined")` → `TokenType.CONSTANT`; otherwise → `TokenType.NUMBER`.
- `structure.punctuations`: extract text via `code.substring(loc.start, loc.end)`. If text matches `Regex("^[+\\-*/%=<>!&|^~?:]+$")` → `TokenType.OPERATOR`; otherwise → `TokenType.PUNCTUATION`.

For each PhraseLocation, create: `SyntaxToken(start = loc.start, end = loc.end, type = resolvedType, text = code.substring(loc.start, loc.end))`.

**Step 2 — Sort and fill gaps:**
- Sort all tokens by `start` position.
- Create a new list. Track `pos = 0`. For each token:
  - If `token.start > pos`: insert a PLAIN token for `[pos, token.start)`: `SyntaxToken(start = pos, end = token.start, type = TokenType.PLAIN, text = code.substring(pos, token.start))`
  - Add the token.
  - Set `pos = token.end`.
- After all tokens: if `pos < code.length`, insert final PLAIN token for `[pos, code.length)`.
- Return the filled list.

**Step 3 — Overlap handling (PITFALL #2 mitigation):**
- When iterating positions, if a new token starts at the same position as an existing token's start (overlap): keep the one with higher "priority". Priority order: STRING > KEYWORD > COMMENT > CONSTANT > NUMBER > FUNCTION > TYPE > OPERATOR > PROPERTY > PUNCTUATION > TAG > PLAIN. If priorities tie, keep the longer token.

**File 2: `SyntaxHighlighterImpl.kt`**
```kotlin
package com.warped.data.highlighting

import com.warped.domain.highlighting.SyntaxHighlighter
import com.warped.domain.highlighting.LanguageDetector
import com.warped.domain.model.SyntaxToken
import dev.snipme.highlights.Highlights
import dev.snipme.highlights.model.SyntaxThemes
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import timber.log.Timber
import javax.inject.Inject
import javax.inject.Singleton

@Singleton
class SyntaxHighlighterImpl @Inject constructor(
    private val languageDetector: LanguageDetector,
) : SyntaxHighlighter {

    // LRU cache: LinkedHashMap with access-order, max 50 entries, evict eldest
    private val cache = object : LinkedHashMap<Int, List<SyntaxToken>>(50, 0.75f, true) {
        override fun removeEldestEntry(eldest: MutableMap.MutableEntry<Int, List<SyntaxToken>>?): Boolean {
            return size > 50
        }
    }

    // Cache key: code.hashCode() xor language.hashCode()
    private fun cacheKey(code: String, language: String): Int = code.hashCode() xor language.hashCode()

    // Maximum code size: 500KB safety cap (OOM pitfall #3 mitigation)
    override suspend fun highlight(code: String, language: String): List<SyntaxToken> {
        if (code.length > 500_000) {
            Timber.w("SyntaxHighlighter: code block too large (%d chars) — returning plain tokens", code.length)
            return listOf(SyntaxToken(0, code.length, com.warped.domain.model.TokenType.PLAIN, code))
        }
        val key = cacheKey(code, language)
        cache[key]?.let { return it }
        return withContext(Dispatchers.Default) {
            val syntaxLanguage = languageDetector.resolveSyntaxLanguage(language)
            val highlights = Highlights.Builder()
                .code(code)
                .language(syntaxLanguage)
                .theme(SyntaxThemes.monokai())   // theme is required by API but we ignore the output
                .build()
            val structure = highlights.getCodeStructure()
            val tokens = TypeMapper.map(structure, code)
            cache[key] = tokens
            tokens
        }
    }
}
```

**Critical rules:**
- Always wrap Highlights calls in `withContext(Dispatchers.Default)` — never block Main thread (CONVENTIONS.md pattern).
- Cache key uses `code.hashCode() xor language.hashCode()` for fast lookup. Hash collisions are acceptable (rare, no security impact).
- 500KB code cap returns single PLAIN token — safe degradation for enormous blocks.
- Call `SyntaxLanguage.DEFAULT` path for json/yaml/sql/plaintext — these are handled by `resolveSyntaxLanguage()` in LanguageDetector.
- `SyntaxThemes.monokai()` is used only to satisfy the Highlights.Builder API contract. Its output is discarded — we use our own SyntaxTheme colors.

Follow conventions: 4-space indent, K&R braces, trailing commas. Timber.w() for warnings (oversized blocks). No KDoc.
