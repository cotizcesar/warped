## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` / `background` (theme-resolved) | Chat background, surfaces |
| Secondary (30%) | `colorScheme.surfaceContainer` (input pill, cards) | Chat input pill, message bubbles, draft card background |
| Accent (10%) | `colorScheme.primary` | Draft play/pause icon tint, LinearProgressIndicator fill (draft + bubble), send affordance |
| Destructive | `colorScheme.error` | Draft delete affordance, "clip unavailable" icon tint |

Accent reserved for: draft play/pause icon tint, draft + bubble LinearProgressIndicator fill, send affordance. Never for error text, never for the delete affordance (error color owns those). Source: Phase 67 contract, extended to draft/bubble progress.

Draft-card color rule (locked by CONTEXT.md discretion — follow bubble/Snackbar conventions): draft card background is `colorScheme.surfaceContainer` (same as input pill / text bubbles); play/pause icon tint `colorScheme.primary`; delete icon tint `colorScheme.error`; duration text `onSurfaceVariant`. No pulsing background, no card recolor during playback — progress bar motion is the only playback-state signal.

Bubble color rule: own-voice bubble uses the exact same bubble chrome as text/image messages (same container color, same corner shape, same padding). Play icon tint `colorScheme.primary`; progress fill `colorScheme.primary` on `surfaceContainerHighest` track; duration `onSurfaceVariant`; "clip unavailable" icon + text `onSurfaceVariant` (informational, not error-red — the file is gone, not a user error).

## Screens / Surfaces (Phase 68 scope)

Exactly two surfaces change, both in `ChatScreen.kt`. No new screens, no new dialogs, no drawer/settings changes. Icon differentiation, model/remote gating, and transcript captions belong to Phase 69 — not this phase.

### Surface 1 — Draft preview card (above `ChatInputBar`)

- Persistent draft card sits directly above the chat input (in the `bottomBar` slot, above `ChatInputBar`, mirroring the Phase 67 recording-row position). Visible whenever VM draft state holds a kept clip (`hasVoiceClip` true, not recording).
- Card contents left-to-right: play/pause toggle + `LinearProgressIndicator` (0..1 fraction of clip duration) + duration readout (`m:ss` total, switching to remaining/elapsed during playback per agent's discretion — must be one fixed convention) + Send (primary, `colorScheme.primary`, same send affordance language as Phase 67 recording row) + Delete (error tint, same X/delete language as Phase 67 cancel).
- Content descriptions: "Play voice draft" / "Pause voice draft" (toggle), "Send voice message" (send), "Delete voice draft" (delete).
- Caption text stays editable alongside the draft; send transmits voice + caption as one bubble (Phase 67 contract, unchanged). Draft card must not cover or disable the caption input.
- Delete removes the audio file immediately — no confirmation dialog, no trash/undo (Phase 67 cancel-discards precedent, locked by CONTEXT.md).
- Sub-1 s clips are rejected at stop time: file deleted, draft card never appears, Snackbar "Recording too short" (`SnackbarDuration.Short` via existing `SnackbarHost` channel). Applies to both manual stop and 60 s auto-stop path (a 60 s clip is never sub-1 s, but the guard sits at the single stop-and-keep choke point).
- TalkBack: draft card announces state via `stateDescription` (Phase 65 pattern) — "Voice draft, 0:12, paused" style; live progress updates at most every 5 s to avoid TalkBack spam (Phase 67 recording-row precedent).

### Surface 2 — History playback bubbles (message list)

- Own sent voice bubbles render a player row inside the existing bubble chrome: play/pause toggle + `LinearProgressIndicator` + duration readout. Same bubble container, corner shape, and padding as text/image messages so Phase 69 transcript captions slot underneath without re-layout (locked by CONTEXT.md specifics).
- Live progress during playback; starting one clip stops any other (single-player discipline — mirrors single-flight inference cancel, locked by CONTEXT.md).
- Content description: "Play voice message, 0:12" / "Pause voice message" (toggle, duration interpolated).
- Playback position resets to 0 on rotation — simple and honest (locked by CONTEXT.md). Rotation during playback pauses and keeps bubble state; user resumes with one tap.
- Missing-file state: bubble renders the same chrome with an informational row — audio-off/blocked-style icon + "Voice clip unavailable" text in `onSurfaceVariant`, no play button. Never a silent drop, never a crash (locked by CONTEXT.md). Exact icon choice within `Icons.Filled` set at executor's discretion.
- Players only on own sent voice bubbles — received/model-side audio is future VF-03, out of scope. No player row on assistant bubbles.
- Stop playback on chat exit (no leaks past screen); pause on audio-focus loss (calls/other-app audio); backgrounding pauses playback and keeps position, resumes with one tap (locked by CONTEXT.md).

### State survival (locked by CONTEXT.md)

- Draft survives rotation (VM-owned state + file on disk). Backgrounding mid-draft keeps the draft (Phase 67 auto-stop-and-keep extends naturally).
- No new gating in this phase — draft/playback available whenever a clip exists; model/remote gating is Phase 69.
