| Token | Value | Usage |
|-------|-------|-------|

| sm | 8px/dp | Compact element spacing, chip internal gaps, card internal gaps |
| md | 16px/dp | Default element spacing, screen horizontal padding |
| lg | 24px/dp | Section padding, dialog internal padding |
| xl | 32px/dp | Layout gaps |
| 2xl | 48px/dp | Major section breaks |
| 3xl | 64px/dp | Page-level spacing |

Exceptions (inherited from 49, retained): 12dp card corner radius + card
content padding, 6dp badge gaps, 20/28/40dp icon and touch-target sizes.

chip-to-input gap is 8dp, banner-to-bubble gap is 4dp, Fuentes items stack
with 4dp spacers. All multiples of 4.

no new text styles):

|------|------|--------|-------------|

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1F1F1E` (`BackgroundDark`/`SurfaceDark`) | Background, surfaces |
| Secondary (30%) | `#2B2B29` (existing card container) | Cards, status chip container, settings card |
| Accent (10%) | `#D97757` (`PrimaryDark`/`PrimaryLight`) | See reserved list below |
| Destructive | `#EF4444` (`ErrorDark`; `#DC2626` in light mode) | Destructive actions + download error text only |

Accent reserved for: "Use in chat" buttons, Send `IconButton` container,
Thinking-toggle active state, focused input border, selected-check icon in
the code-theme dropdown, fetch status-chip spinner track, fuente URL link

body text, card backgrounds, banner surfaces, or error surfaces. Executor
keeps reading colors from `MaterialTheme.colorScheme` / theme tokens so
light mode follows the existing `*Light` variants — no new hardcoded hex.

Notice banner uses no new color: `Icons.Filled.Info` + text in
`onSurfaceVariant` (muted), transparent container. It is a notice, not an
error — never `error` color, never accent.

## Surfaces: New / Retained

### 1. Fetch status chip — transient row above the input bar (WEB-06, WEB-02)

- Placement: full-width transient row pinned directly above `ChatInputBar`
  (inside the `Scaffold` bottom-bar column, 8dp gap to the input card),
  visible only while a URL fetch is in flight. Never a transcript message,
  never persisted in Room.
- Content: 16dp indeterminate `CircularProgressIndicator` (accent track,
  `contentDescription` null — decorative) + `Text("Leyendo página…")` in
  Secondary 14sp Normal, 8dp gap between spinner and text, 8dp horizontal
  padding. Container: transparent (no card, no elevation) so it reads as
  status, not content.
- A11y: the row carries `contentDescription` "Leyendo página. Pulsa Detener
  para cancelar la lectura." Cancellation reuses the existing input-bar Stop
  button (`isGenerating` stays true during fetch; `stopGeneration()` cancels
  both the OkHttp `Call` and the inference Job). No separate cancel button
  on the chip.
- Lifecycle: mounts on fetch start, unmounts on fetch completion, failure,
  or Stop-cancel. While mounted, Send stays swapped to Stop. The chip never
  shows error text — failure unmounts the chip and mounts the E3 banner.

### 2. Fuentes list — numbered sources under grounded answers (WEB-04, WEB-06)

- Placement: rendered directly under a grounded assistant answer, inside the
  same transcript flow (4dp gap below the answer bubble). Non-model UI
  rendered by Compose where possible; plain numbered lines inside the bubble
  where markdown rendering requires it.
- Content: heading `Text("Fuentes")` in Label 12sp SemiBold, then one item
  per fetched page in Secondary 14sp Normal as `"[1] {url}"`. Single-fetch
  phase: normally exactly one item. Items stack with 4dp spacers; long URLs
  wrap normally (no truncation — citations must stay complete).
- Citation markers `[1]`/`[2]` in the answer body are plain model text in
  existing transcript style (no accent, no link styling); only the Fuentes
  URL items use accent link color.
- If the grounded answer carries zero sources, no Fuentes block renders
  (absence is the empty state — never a "Fuentes" heading with no items).

### 3. Model-only notice banner — UI-rendered, never model text (WEB-05)

- Placement: notice row directly above the assistant message it qualifies
  (4dp gap), in transcript flow. Rendered by Compose from fetch state —
  never generated by the model, never error text injected as context.
- Content: `Icons.Filled.Info` 16dp + text in Secondary 14sp Normal,
  `onSurfaceVariant` muted, transparent container, 8dp icon-text gap.
- Copy variants (exactly two, Spanish, see Copywriting Contract):
  offline (`Sin conexión…`) vs fetch-failure (`No se pudo leer la página…`).
  The banner qualifies one message and scrolls with it; it is not a
  Snackbar, not dismissible separately, and never persists as separate state.

### 4. Grounding toggle — Settings screen (WEB-06)

- Placement: new "Web" section card in `SettingsScreen` `LazyColumn`,
  positioned after the Data section card (Data → Web → Display → App →
  Security). Follows the existing section pattern: section header
  `Text` in `titleMedium`, `Card` with 12dp corners, `#2B2B29` container,
  16dp content padding, list `spacedBy(12dp)`.
- Content: row with title (Body 16sp) + description (`bodySmall` 12sp
  Normal, `onSurfaceVariant`) on the left, Material 3 `Switch` on the
  right with `contentDescription` "Grounding web". State persisted via
  DataStore Preferences, default ON. Toggle takes effect on the next sent
  message (no retroactive re-grounding, no restart required).
- When OFF: URL detection is skipped, no fetch, no chip, no Fuentes, no
  banner — chat behaves exactly as pre-50.

## Visual Hierarchy

- Chat (primary screen): focal point remains the transcript column
  (assistant text left / user bubble right). The status chip is
  deliberately recessive (transparent container, muted text, small
  spinner) — it signals activity without stealing focus from the
  transcript. The model-only banner is muted notice styling for the same
  reason. The Fuentes heading is Label-scale so sources read as footnote,
  not content.
- The only accent-colored newcomers are the chip spinner, fuente URL links,
  and the toggle's checked track — all enumerable in the reserved list.
- Settings: focal point stays the section list; the new Web card slots
  between Data and Display with no reordering of existing sections.
