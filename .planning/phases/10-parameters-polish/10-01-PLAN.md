# Phase 10 Plan 01: Parameters & Polish

**One-liner:** Add modelFormat to presets with Room migration, grey out unsupported LiteRT-LM parameters, and handle cross-format preset loading with warnings.

<objective>
Complete the parameter experience for LiteRT-LM:
1. Room migration v8→v9 adds `model_format` to `presets` table
2. PresetEntity + Preset domain model + PresetMappers updated with modelFormat field
3. PresetsScreen shows format badges and handles cross-format loading with warning dialog
4. Parameters (repeatPenalty, contextSize, threads) greyed out when LiteRT-LM engine is active
5. DB version bumped + migration registered
</objective>

<context>
@.planning/phases/10-parameters-polish/10-CONTEXT.md

Key decisions:
- modelFormat TEXT NOT NULL DEFAULT 'GGUF' on presets table (matches local_models)
- Grey-out uses `enabled = false` + alpha modifier on Slider
- Cross-format warning dialog: "This preset was created for [format]. Only compatible parameters will be applied."
- Reuse FormatBadge composable pattern from Phase 9
- Format detection via EngineManager.getActiveEngine()?.type
- LiteRT-LM unsupported: repeatPenalty, contextSize, threads
- LiteRT-LM supported: temperature, topP, topK, seed, maxTokens
</context>

<threat_model>
No new threat surfaces. This plan modifies existing UI components and the Room presets table. Mitigations:
- Migration uses ALTER TABLE ADD COLUMN (no data loss, backward compatible)
- modelFormat defaults to 'GGUF' preserving existing preset data
- No new network endpoints, auth paths, or file access patterns
</threat_model>

### Task 3: Grey out unsupported LiteRT-LM parameters

<type>auto</type>
<behavior>

</behavior>
<implementation>
1. **PresetsScreen.kt**:

2. **PresetsViewModel.kt**:
   - Update `activeFormat` detection from EngineManager in init block
   - Map EngineType to format string: LITE_RT_LM → "LITERTLM", LLAMA_CPP → "GGUF"
</implementation>
