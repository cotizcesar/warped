# Plan 44-02: LlmModelHelper tool plumbing (SKILLS-02, SKILLS-03)

**Phase:** 44 — Agent Skills Lite
**Requirements:** SKILLS-02, SKILLS-03

## Goal

Extend `LlmModelHelper.runInference` with an optional `skills: List<Skill> = emptyList()` parameter. Wire it into `LiteRtLlmHelper` (logs the skill list for now) and `LmStudioHelper` (maps each Tool-category skill to an OpenAI-style `tools[]` entry in the request body).

## Scope

- `app/src/main/java/com/warped/domain/llm/LlmModelHelper.kt` (add `skills` parameter)
- `app/src/main/java/com/warped/data/local/inference/LiteRtLlmHelper.kt` (override + log)
- `app/src/main/java/com/warped/data/remote/provider/LmStudioHelper.kt` (override + map)
- `app/src/main/java/com/warped/ui/chat/ChatViewModel.kt` (pass `uiState.enabledSkills` to `runInference`)
- `app/src/main/java/com/warped/data/remote/dto/LmStudioDtos.kt` (add `ToolsChatRequest` variant if needed)
- `app/src/main/java/com/warped/data/remote/provider/LMStudioProvider.kt` (verify `tools` field already exists or add it)

## Implementation

### 1. `LlmModelHelper.kt` interface change
```kotlin
fun runInference(
    request: ChatRequest,
    enableThinking: Boolean = false,
    skills: List<Skill> = emptyList(),
): Flow<StreamToken>
```
Default to empty list for backward compatibility. Both helpers get a default-impl that ignores `skills`.

### 2. `LiteRtLlmHelper.kt`
Override `runInference(..., skills)`. In the body, log the skill count + IDs with `Timber.d`. Future v2.1 work: register each Skill's underlying `@Tool` method with the LiteRT-LM engine. The current v0.13.1 API doesn't yet expose a tool-registration entry point from a `Skill` value object.

### 3. `LmStudioHelper.kt`
Override `runInference(..., skills)`. For each Tool-category skill, emit an OpenAI-style `tools` entry:
```json
{
  "type": "function",
  "function": {
    "name": "<skill.id>",
    "description": "<skill.description>",
    "parameters": { "type": "object", "properties": {} }
  }
}
```
Attach to the LM Studio request body via the existing `LMStudioProvider` if it already supports a `tools` field; otherwise add a minimal `tools` parameter to the request DTO.

For PromptTemplate-category skills, append the skill's `systemPrompt` to the request's first system message (create one if absent).

### 4. `ChatViewModel.kt`
Pass the active `enabledSkills` from `SkillRepository` to `helper.runInference(request, enableThinking, skills)`. Inject `SkillRepository` via Hilt.
